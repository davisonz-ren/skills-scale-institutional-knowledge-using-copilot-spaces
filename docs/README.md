# OctoAcme Project Management Docs — README

This README serves as the entry point and index for OctoAcme project management processes. It summarizes our high-level approach and provides links to all process documentation in the `docs/` directory.

## Overview of OctoAcme Project Management Processes

OctoAcme follows a **customer-first, iterative approach** to project management that emphasizes clear ownership, data-informed decisions, and continuous improvement. Our process is designed to enable cross-functional teams to deliver value consistently and transparently.

### Core Principles
- **Customer-first**: Prioritize customer value and usability in all decisions
- **Iterative delivery**: Deliver small, testable increments to reduce risk and accelerate feedback
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead with defined responsibilities
- **Data-informed decisions**: Measure impact and iterate based on evidence, not assumptions
- **Psychological safety**: Encourage feedback, learning, and blameless retrospectives

### Project Lifecycle Stages
Our projects follow five key stages:

1. **Initiation** — Validate business need, align stakeholders, define success criteria, and create project one-pager
2. **Planning** — Break work into shippable increments, estimate scope, identify dependencies and risks
3. **Execution** — Build, test, review, and iterate with daily standups and regular demos
4. **Release** — Deploy to production with proper testing, rollback plans, and stakeholder communication
5. **Retrospective** — Capture learnings and convert them into actionable improvements

### Key Roles
- **Project Manager (PM)**: Coordinates delivery, schedules, risk management, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Developers**: Implement features, collaborate on design, and ensure testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs, approvals, and feedback

### Team Values
- Transparency in status and decision-making
- Collaboration across functional boundaries
- Quality through automated testing and peer review
- Continuous learning and improvement
- Balanced delivery of speed and sustainability

## How to Use These Docs

### For New Team Members (Onboarding)
1. **Start here**: Read this README to understand OctoAcme's overall approach and values
2. **Review the [Project Management Overview](octoacme-project-management-overview.md)** for a concise introduction to roles, artifacts, and lifecycle
3. **Explore your role**: Read the [Personas](octoacme-roles-and-personas.md) document to understand your responsibilities and goals
4. **Phase-specific guidance**: As you join a project, reference the relevant stage documents (Initiation, Planning, Execution, Release, Retrospective)

### For Existing Team Members
- **Process reference**: Use these docs as a reference when you need clarification on templates, checklists, or best practices
- **Alignment**: Share relevant sections with stakeholders to ensure everyone follows the same process
- **Continuous improvement**: Propose updates to these docs based on learnings from retrospectives and real project experiences

### For Project Managers
- **Project setup**: Use the Initiation and Planning guides to set up new projects with proper artifacts and stakeholder alignment
- **Ongoing management**: Reference Execution & Tracking and Risk Management docs for day-to-day coordination
- **Retrospectives**: Use the Retrospective guide to facilitate learning sessions and track action items

### For Product Managers
- **Feature planning**: Use the Planning and Initiation docs to define clear success metrics and acceptance criteria
- **Stakeholder communication**: Reference the Communication templates in the Risk Management doc
- **Measuring outcomes**: Track success metrics defined in the project one-pager throughout the lifecycle

### For Developers
- **Understanding workflow**: Review Execution & Tracking for PR conventions, testing standards, and quality practices
- **Planning participation**: Use the Planning doc to understand estimation and backlog refinement
- **Contributing to process**: Participate in retrospectives and suggest improvements based on your experience

### Integration with Copilot Spaces
- Add relevant process docs to `.copilot/` in your project repository to give Copilot Spaces context about OctoAcme standards
- Use these docs to train AI assistants on your team's specific workflows and quality expectations
- Reference these docs when asking Copilot for help with project planning, documentation, or process questions
